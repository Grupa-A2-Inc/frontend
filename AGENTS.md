# Local sprint activity report

Maintain the local file `SPRINT_ACTIVITY_REPORT.md` whenever you complete a bug fix, meaningful investigation, or implementation task for this sprint.

Rules:
- Keep the report concise: one short entry per task.
- Include date, task/bug name, issue summary, root cause when known, files changed, verification, status, and follow-up if needed.
- Mention failed verification only when relevant, and distinguish pre-existing repo failures from failures caused by the current change.
- Do not commit or publish the report. It is listed in `.gitignore` for local professor-facing activity tracking.
